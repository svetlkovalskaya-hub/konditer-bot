# План доработки Telegram-бота

**Дата:** 2026-07-04

## Задачи

1. Улучшить UX сценария выбора торта (п. 2).
2. Поправить мелкие баги: пути к фото, ошибки потока, кавычки (п. 3).
3. Помечать источник заказа в админ-уведомлениях и базе (п. 4).
4. Добавить ежедневное утреннее приветствие кондитеру со списком заказов на сегодня и завтра.
5. Дать кондитеру возможность самостоятельно создавать заказ через панель администратора.

## Подход

### 1. UX сценария торта

- Добавить в клавиатуру выбора вида торта кнопку «← Назад к изделиям» (`callback_data: 'cake_back_to_products'`).
- При нажатии возвращать клиента к выбору продукта с сохранённым именем.
- При выборе вкуса для Наполеона/Медовика давать кнопку «← Назад к списку тортов» наряду с подтверждением.
- При подтверждении торта заменять сообщение с фото на текстовое подтверждение с помощью `editMessageCaption`/`editMessageReplyMarkup`, чтобы не плодить сообщения. Если фото нет — отредактировать текст.

### 2. Мелкие баги

- Использовать `path.resolve(__dirname, '..', '..', '..', cake.photoFile)` или путь, относительный к `process.cwd()`, но стабильный. В `cakeTypes.js` оставить относительные пути, но при отправке разрешать через `path.resolve(process.cwd(), cake.photoFile)`.
- В `createOrderFromSession` обернуть сохранение фото в `try/catch` с нормальной обработкой ошибок потока и сразу добавлять запись в `order_photos` с путём только после успешной записи.
- Исправить кавычку-ёлочку в тексте «Готово» на обычную.
- В `src/index.js` убрать тело `createOrderFromSession` из `handleCallback`, использовать отдельную функцию.

### 3. Источник заказа

- Добавить в таблицу `orders` колонку `source TEXT` через миграцию в `src/db/index.js`.
- В `orderService.createOrder` принимать поле `source` и сохранять его.
- В Telegram-уведомлении админу писать `(TG)` для Telegram-заказов. MAX-бот уже пишет `(MAX)`.
- В панели администратора при просмотре заказов отображать источник.

### 4. Утреннее приветствие

- Добавить зависимость `node-cron`.
- Создать `src/utils/scheduler.js` с cron-задачей на 9:00 утра.
- Задача:
  - Получить заказы на сегодня и завтра.
  - Отсортировать по `delivery_time`.
  - Если хотя бы один заказ есть — отправить админу сообщение:
    - «Доброе утро! Желаю отличного дня и отправляю список ближайших заказов».
    - «Сегодня выдаем заказы» + список.
    - «Заказы к выдаче на завтра» + список.
  - Если заказов нет — не отправлять.
- Запускать планировщик из `src/index.js` после инициализации Telegram-бота.

### 5. Админ: создание заказа

- В `keyboards.mainMenuKeyboard(true)` добавить кнопку «➕ Записать заказ».
- В `src/bot/telegram/admin.js` добавить обработку этой кнопки.
- Сценарий создания заказа админом использует ту же логику, что и клиентский (`newOrder`), но с флагом `isAdminOrder = true`.
- При сохранении заказа из админки:
  - `client_id` = админский `userId` (или специальный идентификатор `admin_manual`).
  - `source = 'admin'`.
  - В уведомлении писать `(Админ)`.
  - После создания возвращать админу в панель.

## Изменённые файлы

- `src/config/cakeTypes.js` — добавить относительные пути, возможно, поле `flavors`.
- `src/utils/keyboard.js` — кнопка «Назад» в `cakeTypeKeyboard`, кнопка «Записать заказ» в админ-меню.
- `src/bot/telegram/scenes/newOrder.js` — улучшение UX, исправление багов, поддержка источника и админского заказа.
- `src/bot/telegram/admin.js` — запуск сценария создания заказа админом.
- `src/bot/telegram/index.js` — обработка новой админ-кнопки, передача флага админ-заказа.
- `src/services/orderService.js` — поле `source`, функции получения заказов по дате.
- `src/db/index.js` — миграция: добавить `source` в `orders`.
- `src/utils/scheduler.js` — новый файл с утренним приветствием.
- `src/index.js` — запуск планировщика.
- `package.json` / `package-lock.json` — добавить `node-cron`.

## Риски и вопросы

- Время приветствия — 9:00 по какому часовому поясу? Сервер Beget, скорее всего, UTC+3 (Москва). Предполагаю московское время. Если нет — уточним.
- При админском заказе `client_id` лучше хранить ID админа или метку `admin_manual`? Рекомендую `admin_<telegramId>`, чтобы заказ не смешивался с заказами клиента.
