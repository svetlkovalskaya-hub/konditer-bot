# Отчёт: MAX-бот и необходимость домена

**Дата:** 2026-07-04

## Что сделано

1. Получен токен для MAX-бота.
2. Токен добавлен в файл `.env` на сервере Beget.
3. Бот перезапущен. В логах появилось:
   - `MAX-бот запущен`;
   - `Telegram-бот запущен`;
   - `Сервер запущен на порту 3000`.

## Проблема

MAX требует **HTTPS webhook** для получения сообщений от пользователей.

Текущий сервер доступен только по IP `159.194.204.27` и не имеет домена. В логах наблюдается ошибка SSL:

```
UNABLE_TO_GET_ISSUER_CERT_LOCALLY
```

Это связано с тем, что библиотека `@maxhub/max-bot-api` пытается использовать polling/webhook, а сервер не может установить безопасное TLS-соединение без корректно настроенного домена и сертификата.

## Проверки

- Обновление системных CA-сертификатов (`ca-certificates`) не решило проблему.
- Проверка PTR-записи по IP не дала полезного домена.
- Сервер Beget не имеет привязанного домена для выпуска Let's Encrypt.

## Решение

Для запуска MAX-бота нужен **домен + HTTPS**.

### План дальнейших действий

1. Приобрести домен (рекомендуется `.ru` или `.рф`).
2. Направить домен на сервер Beget (`A`-запись на `159.194.204.27`).
3. Установить и настроить **nginx** как reverse proxy.
4. Выпустить бесплатный SSL-сертификат через **Let's Encrypt / certbot**.
5. Настроить webhook для MAX-бота:
   - URL: `https://твой-домен.ru/max-webhook`;
   - обработчик POST-запросов в коде бота;
   - отказ от polling в пользу webhook.
6. Добавить на тот же домен будущий сайт (лендинг, блог, визитка). Домен может обслуживать и сайт, и бота одновременно.

## Примечание

Один домен можно использовать одновременно для:
- сайта на основном адресе `https://твой-домен.ru`;
- webhook MAX-бота на `https://твой-домен.ru/max-webhook`;
- возможного webhook Telegram-бота на `https://твой-домен.ru/telegram-webhook`.

Если сайт будет размещён на внешнем конструкторе (Tilda, Wix, WordPress.com), тогда сервер с ботом можно разместить на поддомене `https://bot.твой-домен.ru`.
