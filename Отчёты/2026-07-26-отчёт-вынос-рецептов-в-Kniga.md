# Отчёт: бот «Книга рецептов» переехал в папку Kniga

**Дата:** 2026-07-26

## Что сделано

Бот книги рецептов вынесен из основного проекта `Konditer` в отдельную самостоятельную папку:

```
C:/Users/User/My AI/Konditer/Kniga/
```

Основной проект `Konditer` возвращён в состояние до добавления recipe-бота.

## Новая структура Kniga

```
Kniga/
├── .env.example
├── package.json
├── README.md
├── data/                 # SQLite (создаётся автоматически)
├── uploads/              # временные фото (создаётся автоматически)
└── src/
    ├── index.js          # сервер + запуск MAX-бота
    ├── config/
    │   └── index.js      # MAX_RECIPE_BOT_TOKEN, порт, пути
    ├── db/
    │   └── index.js      # база recipes
    ├── services/
    │   ├── recipeParser.js
    │   └── recipeService.js
    └── bot/
        └── max-recipe/
            ├── index.js
            ├── keyboards.js
            └── session.js
```

## Откаты в Konditer

Убрано:
- `MAX_RECIPE_BOT_TOKEN` из `src/config/index.js` и `.env.example`.
- Таблица `recipes` и её индексы из `src/db/index.js`.
- Запуск recipe-бота из `src/index.js`.
- Удалены папка `src/bot/max-recipe/` и файлы `src/services/recipeParser.js`, `src/services/recipeService.js`.
- Удалена зависимость `cheerio` из `package.json` / `package-lock.json`.

## Проверка

- `node --check` прошёл для всех файлов обоих проектов.
- `npm start` в `Kniga` поднимает сервер на порту 3001 (бот не стартует без токена — ожидаемо).
- `npm start` в `Konditer` возвращается к прежнему поведению (Telegram-бот, планировщик, MAX-бот заказов).

## Как запустить Kniga

```bash
cd Kniga
cp .env.example .env
# добавь MAX_RECIPE_BOT_TOKEN в .env
npm install
npm start
```
